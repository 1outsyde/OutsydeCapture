Task 1: Secure Token Storage & Session Persistence
This solves Item #4 on the launch roadmap — users are getting logged out every time the app relaunches. The root cause is that tokens are only stored in memory (state/context) and are not persisted to secure storage.
Requirements

Install expo-secure-store if not already present:

bash   npx expo install expo-secure-store

Create a token storage utility at utils/tokenStorage.js:

javascriptimport * as SecureStore from 'expo-secure-store';

const ACCESS_TOKEN_KEY = 'outsyde_access_token';
const REFRESH_TOKEN_KEY = 'outsyde_refresh_token';
const USER_DATA_KEY = 'outsyde_user_data';

// Store both tokens after any successful auth action (login, signup, refresh)
export async function storeTokens(accessToken, refreshToken) {
  await SecureStore.setItemAsync(ACCESS_TOKEN_KEY, accessToken);
  await SecureStore.setItemAsync(REFRESH_TOKEN_KEY, refreshToken);
}

// Retrieve tokens on app launch to restore session
export async function getAccessToken() {
  return await SecureStore.getItemAsync(ACCESS_TOKEN_KEY);
}

export async function getRefreshToken() {
  return await SecureStore.getItemAsync(REFRESH_TOKEN_KEY);
}

// Store minimal user data for instant UI hydration before network call
export async function storeUserData(user) {
  await SecureStore.setItemAsync(USER_DATA_KEY, JSON.stringify(user));
}

export async function getUserData() {
  const data = await SecureStore.getItemAsync(USER_DATA_KEY);
  return data ? JSON.parse(data) : null;
}

// Clear everything on logout
export async function clearAuthStorage() {
  await SecureStore.deleteItemAsync(ACCESS_TOKEN_KEY);
  await SecureStore.deleteItemAsync(REFRESH_TOKEN_KEY);
  await SecureStore.deleteItemAsync(USER_DATA_KEY);
}

Update the auth context / Zustand store (wherever global auth state lives):

On app launch, check getAccessToken() and getUserData() from secure storage
If tokens exist, hydrate state immediately (user sees logged-in UI instantly)
Then silently call POST /api/auth/refresh with the stored refresh token to get a fresh access token pair
If refresh succeeds: update stored tokens, user is fully authenticated
If refresh fails (401): clear storage, redirect to sign-in — session has genuinely expired
Add an isLoading state that is true during this bootstrap check and false once resolved — show a splash/loading screen during this phase, never a flash of the login screen


On every successful login, signup, and OAuth completion, call storeTokens(accessToken, refreshToken) and storeUserData(user).
On logout, call clearAuthStorage() AND hit POST /api/auth/logout with the stored refresh token to revoke it server-side.


Task 2: Automatic Token Refresh (API Interceptor)
This solves Item #1 on the launch roadmap — login crashes and silent failures caused by expired tokens. The app needs to transparently refresh tokens when a 401 TOKEN_EXPIRED response is received.
Requirements

Create or update the API client (utils/api.js or services/apiClient.js). If you're using axios, set up an interceptor. If you're using fetch, create a wrapper.

Axios approach (recommended):
javascriptimport axios from 'axios';
import { getAccessToken, getRefreshToken, storeTokens, clearAuthStorage } from './tokenStorage';

const api = axios.create({
  baseURL: process.env.EXPO_PUBLIC_API_URL,
});

// Attach access token to every request
api.interceptors.request.use(async (config) => {
  const token = await getAccessToken();
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// Handle 401 TOKEN_EXPIRED responses
let isRefreshing = false;
let failedQueue = [];

const processQueue = (error, token = null) => {
  failedQueue.forEach((prom) => {
    if (error) {
      prom.reject(error);
    } else {
      prom.resolve(token);
    }
  });
  failedQueue = [];
};

api.interceptors.response.use(
  (response) => response,
  async (error) => {
    const originalRequest = error.config;

    // Only attempt refresh for TOKEN_EXPIRED, not TOKEN_INVALID or TOKEN_MISSING
    if (error.response?.status === 401 
        && error.response?.data?.error === 'TOKEN_EXPIRED' 
        && !originalRequest._retry) {
      
      if (isRefreshing) {
        // Queue this request — another refresh is already in flight
        return new Promise((resolve, reject) => {
          failedQueue.push({ resolve, reject });
        }).then((token) => {
          originalRequest.headers.Authorization = `Bearer ${token}`;
          return api(originalRequest);
        });
      }

      originalRequest._retry = true;
      isRefreshing = true;

      try {
        const refreshToken = await getRefreshToken();
        const { data } = await axios.post(
          `${process.env.EXPO_PUBLIC_API_URL}/api/auth/refresh`,
          { refreshToken }
        );

        await storeTokens(data.accessToken, data.refreshToken);
        processQueue(null, data.accessToken);

        originalRequest.headers.Authorization = `Bearer ${data.accessToken}`;
        return api(originalRequest);
      } catch (refreshError) {
        processQueue(refreshError, null);
        // Refresh failed — session is dead, force logout
        await clearAuthStorage();
        // Navigate to sign-in screen — use your navigation ref or event emitter
        // Example: navigationRef.current?.reset({ index: 0, routes: [{ name: 'Onboarding' }] });
        return Promise.reject(refreshError);
      } finally {
        isRefreshing = false;
      }
    }

    return Promise.reject(error);
  }
);

export default api;

Replace all direct fetch or axios calls throughout the app with this shared api client. Every authenticated request must go through it so the interceptor can handle token refresh transparently.
Critical edge case: The interceptor uses a queue (failedQueue) so that if multiple requests fail simultaneously due to an expired token, only one refresh call is made and all queued requests retry with the new token. Do not skip this — without it, you'll fire multiple refresh calls that race and invalidate each other.

Implement handleAppleSignIn:

javascriptasync function handleAppleSignIn() {
  try {
    // Generate a nonce for security (optional but recommended)
    const nonce = Math.random().toString(36).substring(2, 15);
    
    const credential = await AppleAuthentication.signInAsync({
      requestedScopes: [
        AppleAuthentication.AppleAuthenticationScope.FULL_NAME,
        AppleAuthentication.AppleAuthenticationScope.EMAIL,
      ],
    });

    // CRITICAL: Apple only provides fullName and email on FIRST authorization
    // Capture them immediately and send to backend
    const fullName = credential.fullName
      ? `${credential.fullName.givenName || ''} ${credential.fullName.familyName || ''}`.trim()
      : null;

    // Send identity token to backend for verification
    const response = await api.post('/api/auth/oauth/apple', {
      identityToken: credential.identityToken,
      fullName: fullName,
      email: credential.email, // may be null on subsequent logins
      nonce: nonce,
    });

    if (response.data.isNewUser && response.data.requiresUsername) {
      // Navigate to username selection screen, passing Apple data forward
      // This mirrors the Google OAuth flow you already built
      navigation.navigate('UsernameSelection', {
        authProvider: 'apple',
        appleId: response.data.appleId,
        email: response.data.email,
        fullName: response.data.fullName,
      });
    } else {
      // Existing user — store tokens and navigate to main app
      await storeTokens(response.data.accessToken, response.data.refreshToken);
      await storeUserData(response.data.user);
      navigation.reset({ index: 0, routes: [{ name: 'MainApp' }] });
    }
  } catch (error) {
    if (error.code === 'ERR_REQUEST_CANCELED') {
      // User cancelled — do nothing, this is normal
      return;
    }
    // Show error toast/alert for actual failures
    console.error('Apple Sign-In error:', error);
    Alert.alert('Sign-In Failed', 'Something went wrong with Apple Sign-In. Please try again.');
  }
}
