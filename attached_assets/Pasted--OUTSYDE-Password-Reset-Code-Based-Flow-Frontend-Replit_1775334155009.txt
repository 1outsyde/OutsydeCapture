# OUTSYDE — Password Reset: Code-Based Flow (Frontend / Replit)

## Context

The current Forgot Password screen exists but doesn’t follow the standard mobile password reset pattern. We need a complete multi-step flow that keeps the user inside the app the entire time — no deep links, no switching to a browser.

The backend team (Cursor) is building three endpoints in parallel. Code against them now.

### Backend Endpoints

1. `POST /api/auth/forgot-password/send-code`
- Request: `{ email }`
- Response (always 200): `{ success: true, message: "If an account exists with that email, a reset code has been sent." }`
- Sends a 6-digit code to the user’s email via Resend
1. `POST /api/auth/forgot-password/verify-code`
- Request: `{ email, code }`
- Success: `{ success: true, resetToken: "<token>" }`
- Failure: `400 { success: false, error: { code: "INVALID_CODE" | "TOO_MANY_ATTEMPTS", message: "..." } }`
1. `POST /api/auth/reset-password`
- Request: `{ resetToken, email, newPassword }`
- Success: `{ success: true, message: "Password has been reset successfully." }`
- Failure: `400 { success: false, error: { code: "INVALID_TOKEN" | "WEAK_PASSWORD", message: "..." } }`

### Design System

- **Background**: near-black (#080C08)
- **Primary text**: warm cream (#F0EAD6)
- **Secondary text**: muted cream with ~60% opacity
- **Primary button**: forest green (#3A9E3A), rounded corners, full width
- **Input fields**: dark surface (#1A1A1A or similar), cream text, subtle border
- **Accent / links**: burnished gold (#C9933A)
- **Headings**: Syne font
- **Body text**: DM Sans font
- **Error text**: soft red (#E74C3C or similar)
- **Success text**: green matching primary button

Match the exact look and feel of the existing Sign In screen (see the screenshots — dark background, green buttons, cream text, gold accents).

## What to Build

Replace the current ForgotPasswordScreen with a single screen that has **three steps** managed by internal state (not three separate screens — keep it as one screen with step transitions so the back button works naturally).

### Step 1: Enter Email

**Layout:**

- Back arrow in top left (navigates back to Sign In)
- Heading: “Reset Password” (Syne, large, cream)
- Subheading: “Enter the email address associated with your account” (DM Sans, muted cream)
- Email input field (same style as Sign In screen inputs)
- “Send Code” button (full width, green, same style as “Sign In” button)
- Below button: “Remember your password? **Sign in**” link in gold

**Behavior:**

- Validate email format before sending (basic regex — must contain @ and a dot)
- If invalid format: show inline error below the field in red: “Please enter a valid email address”
- On tap “Send Code”: disable button, show spinner inside button, call `POST /api/auth/forgot-password/send-code` with `{ email }`
- On response (always 200): transition to Step 2, pass the email forward
- On network error: show toast/alert: “Something went wrong. Please check your connection and try again.”

### Step 2: Enter Verification Code

**Layout:**

- Back arrow in top left (goes back to Step 1, preserving the email)
- Heading: “Check Your Email” (Syne, large, cream)
- Subheading: “We sent a 6-digit code to **[email]**” (DM Sans, muted cream, with the email in bold/cream)
- **6 individual digit input boxes** in a row (same pattern as the existing phone verification OTP screen):
  - Each box holds 1 digit
  - Auto-advance to next box on input
  - Auto-submit when all 6 digits are entered
  - Support paste of full 6-digit code (split and fill all boxes)
  - Backspace moves to previous box and clears it
  - Boxes should be ~48x56px, dark surface background, cream text, centered digit, subtle border that highlights gold (#C9933A) on focus
- Below the code boxes: countdown timer showing “Code expires in X:XX” (start at 10:00, count down)
- Below timer: “Didn’t receive a code? **Resend**” link in gold
  - Resend is disabled for 60 seconds after sending (show countdown: “Resend in 45s”)
  - After 60 seconds, Resend becomes tappable and calls the send-code endpoint again
  - Max 3 resends shown to user (after 3: “Maximum attempts reached. Please try again later.”)

**Behavior:**

- When all 6 digits are filled: automatically call `POST /api/auth/forgot-password/verify-code` with `{ email, code }`
- Show a loading indicator while verifying
- On success: store the `resetToken` from the response, transition to Step 3
- On `INVALID_CODE` error: shake the input boxes (subtle animation), clear all boxes, show error text below: “Invalid code. Please try again.” Refocus on first box.
- On `TOO_MANY_ATTEMPTS` error: show error text: “Too many failed attempts. Please request a new code.” Clear boxes, show the Resend link prominently.
- If the countdown timer hits 0:00: show message “Code has expired” and prompt to resend

### Step 3: Set New Password

**Layout:**

- Back arrow in top left (goes back to Step 1 — NOT Step 2, since the code is consumed)
- Heading: “Create New Password” (Syne, large, cream)
- Subheading: “Enter your new password below” (DM Sans, muted cream)
- “New Password” input field with eye icon toggle (show/hide password) — same style as Sign In password field
- “Confirm Password” input field with eye icon toggle
- Password requirements text below inputs (muted, small):
  - “At least 8 characters” — turns green with a checkmark when met
- “Reset Password” button (full width, green)
- The button is disabled until both fields have 8+ characters and both fields match

**Behavior:**

- On tap “Reset Password”: disable button, show spinner, call `POST /api/auth/reset-password` with `{ resetToken, email, newPassword }`
- On success: show a success state:
  - Green checkmark icon (large, centered)
  - “Password Reset!” heading
  - “Your password has been updated successfully.” subtext
  - “Sign In” button (full width, green) that navigates back to the Sign In screen
  - Auto-navigate to Sign In after 3 seconds if user doesn’t tap
- On `INVALID_TOKEN` error: show error: “Your reset session has expired. Please start over.” with a “Start Over” button that goes back to Step 1
- On `WEAK_PASSWORD` error: show inline error below password field: “Password must be at least 8 characters”

## Step Transitions

Use a state variable like `step` (1, 2, or 3) and render the appropriate content conditionally. Use `Animated` for smooth fade or slide transitions between steps if possible, but don’t over-engineer — a simple conditional render is fine.

Store these in component state across steps:

- `email` — entered in Step 1, used in Steps 2 and 3
- `resetToken` — received in Step 2, used in Step 3
- `step` — current step (1, 2, or 3)

## API Integration

Add these methods to your API client (`api.ts` or wherever API calls are centralized):

```typescript
// Password Reset - Send Code
export async function sendPasswordResetCode(email: string) {
  return api.post('/api/auth/forgot-password/send-code', { email });
}

// Password Reset - Verify Code
export async function verifyPasswordResetCode(email: string, code: string) {
  return api.post('/api/auth/forgot-password/verify-code', { email, code });
}

// Password Reset - Set New Password
export async function resetPassword(resetToken: string, email: string, newPassword: string) {
  return api.post('/api/auth/reset-password', { resetToken, email, newPassword });
}
```

## Edge Cases to Handle

- **Keyboard management**: The code input boxes should auto-focus the first box when Step 2 appears. The keyboard should stay open between boxes. Use `KeyboardAvoidingView` to prevent the inputs from being hidden behind the keyboard.
- **App backgrounding**: If the user leaves the app and comes back during Step 2, the timer should still be accurate (calculate remaining time from when the code was sent, not from a decrementing counter).
- **Paste support**: If the user copies the 6-digit code from their email notification and pastes, it should fill all 6 boxes.
- **Fast typers**: The auto-advance between boxes must be responsive — no lag or skipped digits.
